# FUnlock v2.5 pro 验收审核清单

## 使用方式

- v2.5 负责实施。
- pro 负责按下面清单逐项验收。
- 每项结果标注：Pass / Fail / Conditional Pass。
- Critical 失败必须阻断发布。

## Critical

1. 解锁冷却机制生效  
   - 解锁成功后 5 秒内不触发新的自动解锁。

2. 锁屏后首次解锁缓冲生效  
   - 自动锁屏后 0.8 秒内不立即触发解锁。

3. 事件日志不破坏现有主流程  
   - 原有 `unlocked / locked:*` 事件仍可正常写入。

4. 不出现“人在附近但永远无法自动解锁”的回归

## Important

5. 新日志能区分“已尝试”和“已确认”  
   - 存在 `unlocked + unlock_confirmed / unlock_failed`。

6. 事件字段包含 `result / latencyMs / source`  
   - 字段顺序兼容现有消费方。

7. TelemetryLogger 包含新增字段  
   - CSV 含 `Result / LatencyMs / InjectTime / ConfirmTime`。

8. 3 秒内同类事件去重有效  
   - `events.log` 不再高频重复同类型事件。

## Minor

9. 日志格式统一、字段完整、易读

10. 默认参数合理，后续具备可调空间

## 回归场景

- 离开 -> 靠近 -> 自动解锁
- 手动锁屏后不被自动解锁误触发
- 屏保启动/退出
- 显示器休眠/唤醒
- 解锁失败后弹窗告警逻辑
- 事件日志增长与轮转预期
